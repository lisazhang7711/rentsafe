# 安居安全评估 · 房屋安全评估平台

输入小区名或地址，约 15–30 秒生成一份「租房 / 买房前的安全体检报告」。
纯静态站点，无后端，可直接部署到 GitHub Pages。

## 目录

```
rentsafe/
├── index.html        落地页（价值主张 + 搜索入口 + 定价 + 说明）
├── assess.html       评估工作台（输入 → 检索 → 报告）
├── css/style.css     样式（含 @media print 打印样式）
├── js/config.js      Key 与检索参数配置
├── js/amap.js        高德 JS API 封装（联想 / 地理编码 / 周边搜索 / 小地图）
├── js/model.js       六维评分模型、检索清单、清单生成
├── js/render.js      报告渲染（总分环、雷达图、表格、清单）
└── js/app.js         交互逻辑（联想、进度、候选、对比、分享）
```

## 本地运行

```bash
cd rentsafe
python -m http.server 8791
# 打开 http://127.0.0.1:8791/index.html
```

> 必须用 http 打开，直接双击 `file://` 会因浏览器限制无法加载地图与跨域请求。

## 部署（GitHub Pages）

把 `rentsafe/` 整个目录推到仓库根目录或 `/docs`，Pages 选对应分支与目录即可。
注意加一个空文件 `.nojekyll`，避免 Jekyll 处理。

## Key 与安全（上线前必做）

- 默认使用站点内置的高德 **Web 端(JS API)** Key，写在 `js/config.js`。
- **Web 服务 REST 接口不接受这个 Key 类型**（会返回 `USERKEY_PLAT_NOMATCH`），所以全站只用 JS API。
- ⚠️ **这个 Key 与安全密钥曾以明文提交进 Git 历史，必须轮换**：
  高德控制台 → 应用管理 → 该 Key → 重新生成 Key 与 安全密钥 → 同时配置**域名白名单**
  （至少 `lisazhang7711.github.io`）→ 再清理 / 重写 Git 历史。
  静态前端藏不住 Key，域名白名单是唯一有效的防线。
- 代码侧还加了一层来源校验：`js/config.js` 的 `allowedHosts`，不在名单里的域名不会带 Key 去请求高德。
  本地用局域网 IP 调试：`localStorage.setItem('rentsafe.cfg', JSON.stringify({host: location.hostname}))`。
- 不想把 Key 放进仓库：新建 `js/config.local.js`（已在 `.gitignore`）
  `window.RS_LOCAL = { key: 'xxx', sec: 'yyy' };`，并把 `js/config.js` 里的默认值清空。
- 换 Key 的优先级：URL 参数 `?key=xxx&sec=yyy` > localStorage > `config.local.js` > `config.js` 默认值。

## 检索半径（分级，不是统一 3 km）

`js/model.js` 的 `QUERIES` 里逐类配置：公交 1 km、便利店/加油站/变电站/垃圾站 1.5 km、
超市/菜场 2 km、公园/地铁/派出所/殡仪馆 3 km、医院 5 km、消防救援站 6 km。
对外文案统一引用 `RS.model.RADIUS_TXT`，改半径时一并改这里。

### 优先按 POI 类型检索，关键词只作兜底

`QUERIES` 里每类都可以带一个 `type`（高德 POI 类型名）。有 `type` 时 `amap.js`
会传空关键词做纯类型检索；该地无数据（`no_data`）时自动退回 `kw`。

**为什么要按类型检索**：关键词召回要求 POI 名字里含有该词，但大量门店名字里
根本没有类型名。实测忠实里西区同一坐标：

| 检索方式 | 结果 |
|---|---|
| 关键词「便利店」 | 最近一家 537 m |
| `type=便利店` | 共 111 家，最近一家 16 m |

按类型检索能一次性召回 便利蜂、京客隆便利店、惠佳美食品店、易捷便利店、7-ELEVEn
——这些名字里都没有"便利店"三个字。同理 `type=药房` 能召回叮当快药。

堆品牌词补是补不完的，且高德对长 `|` 串的处理**不稳定**：实测「物美|便利蜂」
两个词都生效，但「便利蜂|物美|罗森|全家|好邻居」只召回了第一个词。
所以 `kw` 控制在 3 个近义词以内，覆盖面靠 `type` 而不是靠长串。

**实测可用的类型名**：卫生院 / 药房 / 公园 / 超级市场 / 便利店 /
地铁站 / 加油站 / 陵园。
**实测 `no_data`、只能靠关键词的**：消防队、消防站、派出所、警务站、体育场、
菜市场、农贸市场、公交站、变电站、垃圾站、环卫设施、殡仪馆。

**已下线：学校（小学 / 中学）**。本工具只做安全与应急口径，学区、学位与就学
不属于评估范围，因此 `QUERIES` 里不再检索小学与中学。

**唯一的例外是医院**：高德的「医院」类型把医美、口腔、诊所、社区卫生服务中心
全算进去，5 km 内 600 条，而类型检索按距离排序，前 100 条被近处诊所填满，
真正的大医院一条都进不来（实测过滤后 `firstBig` 为空）。关键词检索按相关性排序，
第一页就能召回「首都医科大学附属首都儿童医学中心」。所以医院类**不要**加 `type`。

放宽会串进同名不同类的点（查「广场」会命中「XX出口」这种立交桥出口），
由 `model.js` 的 `TYPE_KEEP`（按 POI 类型）和 `NAME_DROP`（按名字）两层收口；
消防和警务还各有一条优先级链：优先取正规消防站 / 正式派出所，
取不到才退到微型消防站 / 社区警务工作室。

### 单页上限与分页

高德单页最多 50 条，旧的 `pageSize:30` 会把高密度类别直接截断（实测便利店 64 家只读回 30 家）。
现统一取 50 条，并对高密度类别翻页：便利店 `pages:3`、超市与医院 `pages:2`。

翻页之间**必须留间隔**（`amap.js` 的 `PAGE_GAP = 260`）。实测连续请求第 2、3 页
会被限流返回 `error`，表现为便利店数量在 50 / 94 之间随机波动——
拿到一页还是两页全看运气。

## 评分口径

总分 = 六维加权和 × 80% + **模式专项** × 20%。

### 六维权重（租 / 买两套刻意相同）

| 维度 | 权重 | 主要依据 |
|---|---|---|
| 应急医疗 | 19% | 综合医院（排除口腔/宠物/社区卫生服务中心）、基层卫生机构、药店 |
| 消防安全 | 18% | 消防救援站距离、可疏散开阔地、楼层与房龄修正 |
| 断电韧性 | 18% | 超市、菜市场、便利店、药店的可达性与密度 |
| 治安门禁 | 19% | 派出所距离 + 门禁物业 + 是否合租 / 低层 |
| 生活保障 | 16% | 地铁、公交、采买（不含学区与就学） |
| 环境风险 | 10% | 加油站、变电站、垃圾站、殡葬设施的临近扣分 |

**两套权重为什么一样（这是踩坑后改回来的）**：原先按直觉给了两套不同权重
（租房 safe 20%/env 8%，购房 safe 14%/env 22%），结果忠实里实测
**购房 91.5 反而高于租房 91.2**。原因是加权平均的性质——六维不可能同时满分，
谁把权重压在「当前较弱的维度」上谁的总分就更低；忠实里最弱的两维恰好是治安(82.8)
和消防(96.2)，而租房最看重的就是治安，于是租房更低。
「购房口径更严格、分数却更高」讲不通。

回到事实本身：医疗、消防、断电、治安这些都是**位置**的属性，不因为你租还是买而变化。
真正随交易形态变的只有两件事，各自单独处理：

1. **交易层面的风险完全不同** → 见下面的「模式专项」
2. **同样的嫌恶设施**，租客承担阶段性体验损失，业主承担永久估值折损 →
   购房口径下环境扣分统一乘 `ENV_MODE_MUL.buy = 1.45`。
   只对扣分生效，不会因为环境干净而给购房额外加分。

方向因此永远成立：**购房口径不会比租房更宽松**。

### 模式专项（占总分 20%，两个口径问不同的题）

| | 租房专项「租约与租住稳定」 | 购房专项「产权与资产稳健」 |
|---|---|---|
| 问什么 | 打算签多久、房东要求的付款方式、是否合租 / 隔断 | 产权是否已核验、土地剩余年限、周边规划是否查过 |
| 未填怎么算 | 按「未确定」扣（−5 / −5） | 按「未核验」重扣（−14 / −9 / −8） |
| 为什么 | 没写进合同的租期不受保护 | 买房不查产权是最大的单点风险，不能默认安全 |

因为「未核验」扣得更狠，同一个地址、表单全部留空时两个口径自然拉开约 4 分
（忠实里实测：租房 91.1，购房 86.6）；把专项里的信息全部填成已核实后两者趋于一致——
这正说明差异全部来自交易本身，而不是同一套标准换了加减法。

### 距离分与密度分的参数（区分度的总闸门）

集中放在 `js/model.js` 顶部，**不要在十几个 `distScore(...)` 调用点各自改**：

| 参数 | 旧值 | 新值 | 影响 |
|---|---|---|---|
| `MISS_SCALE` | 无（直接给 40–55 分） | `.55`（落到 22–30） | 搜不到资源不再接近及格，远郊才掉得下去 |
| `EXCEED_CUT` | 8 分 | 18 分 | 5 km 的医院和 40 km 的医院不再几乎同分 |
| `DENSITY_TIERS` | `n × unit` 封顶，5 家即加满 | 六档阶梯，60 家才到顶 | 城区不再集体白拿同一份密度满分 |

改完之后同一批对照位置（核心区 / 城区一般地段 / 五环外成熟社区 / 远郊新盘 /
什么都搜不到）实测总分 **89.9 → 86.0 → 75.5 → 64.4 → 48.4**，跨度 41.5 分，
A/B/C/D 四个等级都能跑到；改之前城区几个样本全挤在 90 分一线。

等级：≥85 A，70–84 B，55–69 C，<55 D。

## 已知边界

- 报告里两种距离并存：高德周边搜索给的**直线距离**（用于排序粗筛）+ 路径规划算出的
  **实际步行 / 驾车距离与耗时**。两者分开标注，不做直线折算。
- POI 数据来自高德，个别点位可能过时或缺失；所有点位都列在报告里，可自行复核。
- **必须串行检索，不要改回并发**（2026-10-09 实测）：同样一批 15 个关键词，
  3 路并发 + 200 ms 间隔下有 6 个被高德限流返回 `error`（且这些错误一度被静默丢弃，
  直接表现为报告里整类资源人间蒸发）；改成单路串行 + 350 ms 间隔后 15/15 全部成功。
  现在是 16 类资源串行检索 + 最多 9 条路径规划串行（≥300 ms 间隔），实测约 10–20 秒。
  若某天又出现大面积「未检索到」，先把 `js/config.js` 的 `gap` 调大到 500 再说。
- 未提供房屋质量检测、消防验收、法律尽调，报告页脚已声明。
- 定价页只提供已实现的服务；人工定制类尚未开通，开通前不收费。
